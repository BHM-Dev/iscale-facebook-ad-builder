# Codex Brief — Campaign Intelligence: fix the overlap with Compass, kill the wall-of-text summary

## Why

Three things Steve flagged after using Creative Compass + the new Intelligence drawer live:

1. **Real, observed overlap/conflict.** Compass flagged ad set `RHO v2 - HORSE & STABLE - CAPI` as
   "losing money" (RT ROAS 0.59x) using **today's** numbers (Compass reads whatever date preset is
   selected at the top of Campaign Performance — it was "Today" at the time). In the same moment,
   Intelligence's niche table showed the same underlying ad set, rolled up under its "HORSE & STABLE"
   niche row over **the last 7 days** (Intelligence has its own, independent date-preset selector,
   currently hardcoded to default to `last_7d` regardless of what the page's own selector is set to),
   as the single best scale candidate in the account (+53% ROI, "Scale +20%"). Two different answers
   to "does this need attention," shown on the same page, with no visible explanation of why they
   disagree — a real trust problem, not a hypothetical one.
2. **The AI summary is a wall of text nobody reads.** It's a single 3-5 sentence paragraph
   (`_generate_summary` in `backend/app/api/v1/intelligence.py`) generated by a Claude call whose
   entire prompt is built from data that is *already fully computed* before the call happens — the
   `rows` list (niche/spend/revenue/profit/roi/cpl/verdict/confidence/suggested_action_label) and the
   deterministic `action_queue` (already correctly sorted by profit/ROI/confidence). The AI call exists
   only to restate that data as prose, and roughly half the prompt is anti-hallucination guardrails
   telling it not to contradict the very data it's summarizing. That's the root cause of "one big
   paragraph I won't read" — it's assembled from a table Steve could just look at directly, if it were
   presented better.
3. **Grain confusion, worth making explicit in the UI, not just in a Slack answer.** Confirmed by
   reading the code: **Compass operates at individual ad-set grain**, using whatever date range is
   currently selected on the Campaign Performance page itself. **Intelligence operates at niche grain**
   (`_extract_niche` in `intelligence.py` parses a niche label out of each ad set's name, then
   `_aggregate_by_niche` sums every ad set — potentially several, potentially spanning multiple
   campaigns — that share that label), using its own independently-selected date range. Neither
   labels its own grain or window prominently enough for a user to catch a disagreement at a glance.

## Scope

Two files: `backend/app/api/v1/intelligence.py` (not a trigger file, but flag if you touch
`facebook_service.py` for anything) and `frontend/src/pages/CampaignPerformance.jsx` (specifically the
`CampaignIntelligencePanel` component, and the `CreativeCompass` component's header for the labeling
piece).

### 1. Sync Intelligence's default date window to the page's, so silent disagreement stops being the default case

Today: the page's date-range selector (`DATE_PRESETS`: today/yesterday/last_3d/last_7d/last_14d/
last_30d/custom) and Intelligence's own selector (`INTELLIGENCE_PRESETS`: yesterday/last_3d/last_7d/
last_14d/last_30d/weekdays_mtd/weekends_mtd/custom) share most of their preset values verbatim, but
`CampaignIntelligencePanel`'s `preset` state defaults to a hardcoded `initialPreset || 'last_7d'`
independent of whatever the page itself is set to.

Fix: pass the page's current `datePreset` into `CampaignIntelligencePanel` as a new prop, and use it to
seed the initial `preset` state whenever it maps onto one of `INTELLIGENCE_PRESETS`'s values (all of
them except `today`, which Intelligence doesn't have — fall back to `last_7d` only in that one case,
since "today" niche-level rollups aren't very meaningful with an AI/queue built for trend detection).
This only changes the **default** — Joel can still deliberately pick a different window inside the
drawer for real trend analysis, which is a legitimate, intentional use of Intelligence Compass doesn't
try to replicate. The goal is just: if he hasn't touched Intelligence's own selector, it starts aligned
with what he's already looking at, instead of silently defaulting to a different clock.

### 2. Label both surfaces' window/grain explicitly

- **Creative Compass** header (`CreativeCompass` component,
  `frontend/src/pages/CampaignPerformance.jsx`): its subtitle currently reads "Rule-based starting
  points from the metrics already loaded below. Nothing here is an opaque score." Add the active date
  range to this line (Compass already has access to whatever `datePreset`/date range the page is using
  — thread it through as a prop) — e.g. "...loaded below, for `{dateRangeLabel}`. Nothing here is an
  opaque score." Also worth a one-word grain cue since it's genuinely ambiguous without reading code:
  make clear these are **ad sets**, not campaigns or niches (e.g. the section label could read "Ad sets
  that need attention" instead of the current bare "Needs attention" — small copy change, high value).
- **Campaign Intelligence** drawer header already shows its own preset label prominently
  ("Last 7 days" in the observed session) — keep that, but add a one-word grain cue too, e.g. change
  "Action queue · tracking checks · niche decisions" to make "niche" read as the operative word it
  already is (it already says niche — just don't lose it when you touch this file; don't accidentally
  genericize the copy while doing the rest of this work).

Do not attempt to merge Compass's ad-set-level rules and Intelligence's niche-level rollup into one
computation in this pass — that's a real, larger consolidation project (reconciling two different
grains and two independently useful time windows into one model), not something to fold into a
UI-labeling and summary-formatting pass. Flag it as a follow-up idea in your handoff notes if you want,
but don't build it now.

### 3. Kill the wall-of-text paragraph — restructure into a deterministic headline + reasons per action-queue item

**Backend (`backend/app/api/v1/intelligence.py`):**

`_build_action_queue` (currently ~line 233) already sorts every row correctly by profit/ROI/confidence
before truncating to strings like `f"{r['niche']} ({r['suggested_action_label']})"` — throwing away
the very numbers that would explain *why* to a reader. Change it to return structured objects instead
of bare strings, e.g.:

```python
{
    "niche": r['niche'],
    "action_label": r['suggested_action_label'],
    "reason": _format_reason(r),  # new helper, deterministic, no LLM
}
```

Where `_format_reason(r)` builds a short one-line string from data already on the row — something like
`"53% ROI on $309 spend · high confidence"` for a scale row, or `"-56% ROI, -$196 profit · high
confidence"` for a cut/pause row, or `"0% ROI, $-50 · medium confidence"` for watch. Keep it to one
line, numbers only, no adjectives beyond what the data supports — this is meant to answer "why is this
here" at a glance, not to editorialize.

Then, for the long-form `_generate_summary` Claude call (~line 416): **replace it with a deterministic
one-sentence headline, no LLM call.** Every input to the current prompt (queue counts, top scale
candidate, top cut candidate) is already sitting in `action_queue` after sorting — you don't need an
API call to say "3 niches cleared to scale, 5 flagged for pause review — start with HORSE & STABLE
(+53% ROI)." Build that sentence directly from `action_queue['scale'][0]` /
`action_queue['cut_or_pause'][0]` / the list lengths. This also means:
- Zero hallucination risk (nothing left to hallucinate — it's a template over already-sorted data)
- Zero added latency/cost per drawer-open (no more Claude round trip for this endpoint)
- Consistent with how Compass already works (transparent rule text, no opaque AI score) — this pass
  makes Intelligence match that same house style instead of being the one AI-narrative outlier on the
  page

If you think a short bit of AI-written color commentary is still worth keeping (this is a genuine
judgment call, not a hard requirement), the fallback is to keep a *much* narrower Claude call
constrained to one sentence instead of 3-5, but I'd only do that if the deterministic headline turns
out to feel thin in practice — try the deterministic version first, it's simpler, cheaper, and matches
the rest of this page's philosophy. Either way, remove the now-unused
`_sanitize_summary_actions`/`_sanitize_summary_niche_names` guardrail functions if you drop the LLM
call entirely (they exist only to patch AI output after the fact).

Note while you're in this file: the existing Claude call uses model id `claude-sonnet-4-6` — per this
repo's own house rule, never touch/rely on a specific Anthropic model id without confirming it against
`/v1/models` first. Moot if you drop the call; flag it in your handoff notes if you keep it.

**Frontend (`CampaignIntelligencePanel` in `frontend/src/pages/CampaignPerformance.jsx`):**

- Replace the current violet "AI summary" box (`data.summary` rendered via `<MarkdownAnswer>`) with:
  a single bold headline line at the top (from the new deterministic summary field — keep the field
  name `summary` if you like, or rename to `headline`, your call, just update both sides together), no
  paragraph styling needed since it's one sentence.
- Update the Action Queue lane cards (`data.action_queue[lane.key]`, currently rendered as
  `<li className="truncate">{item}</li>` where `item` was a bare string) to render the new structured
  objects: niche name bold on one line, the `reason` string small/muted directly underneath. This is
  the actual fix for "there's gotta be a better way of providing the analysis" — the reason a media
  buyer needs is already in the data, it just wasn't reaching the screen.
